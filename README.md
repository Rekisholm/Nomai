# Nomai

## Functionality

- Runs local Docker-based vulnerable web application scenarios.
- Captures HTTP request IDs and database row/cell read-write provenance.
- Reconstructs request-to-data-to-request causal chains from a final attack request.
- Evaluates recovered attack chains against the request IDs printed by each attack script.
- Produces JSON metrics and interactive provenance graphs for paper experiments.

## Architecture

```text
HTTP request with X-Request-Id
  -> instrumented application/database access logs
  -> PostgreSQL CDC write capture
  -> offline row-level or cell-level backtrace
  -> causal graph and precision/recall/F1 metrics
```

Main directories:

| Path | Purpose |
| --- | --- |
| `scripts/` | Unified experiment runner for scene startup, traffic, attacks, data collection, and analysis. |
| `examples/` | Docker Compose scenarios and attack scripts. |
| `examples_locust/` | Benign background-traffic generators. |
| `cdc_listener/` | PostgreSQL CDC consumers for row-level and cell-level write logs. |
| `analysis_cell/` | Current cell-level provenance backtrace implementation. |
| `analysis/` | Legacy row-level backtrace, pruning, and evaluation utilities. |
| `analysis_llm/` | Optional LLM-assisted analysis components. |
| `java_agent/`, `rust_sqlparse*` | Instrumentation and SQL-rewrite support components. |
| `runs/` | Experiment outputs generated by the runner. |

## Requirements

- Linux host with Docker and Docker Compose.
- Python environment for host-side scripts.
- Python packages:

```bash
pip install -r requirements.txt
```

Optional components:

- `analysis_llm/.env` with `DEEPSEEK_API_KEY` for LLM mode.
- Rust toolchain for Rust SQL parser experiments.
- JDK and Maven for Java-agent development.

## Run One Example

The following commands run one complete Airflow experiment. Replace
`paper_airflow_01` with any experiment name.

```bash
./run_scene.sh start paper_airflow_01 airflow --build --cell-cdc
./run_scene.sh normal paper_airflow_01 airflow 120
./run_scene.sh attack paper_airflow_01 airflow
./run_scene.sh stop paper_airflow_01 airflow
./run_scene.sh analysis paper_airflow_01 airflow --mode all
```

Outputs are written to:

```text
runs/paper_airflow_01/airflow/
```

## Useful Commands

```bash
# Start without rebuilding images.
./run_scene.sh start <experiment> <scene> --cell-cdc

# Check running containers and CDC status.
./run_scene.sh status <experiment> <scene>

# Run only one analysis mode.
./run_scene.sh analysis <experiment> <scene> --mode basic
./run_scene.sh analysis <experiment> <scene> --mode priority
./run_scene.sh analysis <experiment> <scene> --mode llm

# Run a priority-budget sweep for an existing run.
./run_scene.sh budget_sweep <experiment> <scene>
```

## Log Format

Read and write logs are JSON Lines files. The analysis pipeline expects stable
request IDs and database object identifiers.

Read log example:

```json
{"time":"2026-01-01T00:00:03Z","event":"select","rid":"REQ_A","tbn":"items","pks":["1"],"seq":2,"xmin":123,"xmax":125}
```

Cell-level write log example:

```json
{"time":"2026-01-01T00:00:01Z","event":"update","rid":"REQ_B","tbn":"items","pk":"1","xid":124,"seq":0,"cells":[{"col":"payload","new":"<script>alert(1)</script>"}]}
```
